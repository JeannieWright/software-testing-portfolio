# Programming Languages & Tools

This section highlights how I use programming languages and development tools to validate user interfaces, investigate defects, verify backend data, test integrations, and support software quality assurance workflows.

---

## Programming Languages I Use in QA

### 🔹 JavaScript

- Write and maintain browser-based UI validation and automated test scripts.
- Validate page behavior, form fields, user interactions, and client-side business rules.
- Inspect DOM elements and JavaScript console output when investigating front-end defects.
- Support automated web testing with Playwright and WebdriverIO.
- Test third-party integrations and interactive functionality in web and OTT applications.

### 🔹 TypeScript

- Develop maintainable Playwright test scripts with clearly defined data types.
- Use interfaces and type annotations to organize test data, reusable functions, and automation components.
- Reduce test-script errors by identifying invalid values before execution.
- Support scalable test suites for responsive and interactive web applications.

### 🔹 SQL

- Execute database queries to validate backend data and application processing.
- Compare information displayed in the user interface with records stored in Microsoft SQL Server and MySQL.
- Validate database insertions, updates, and deletions initiated through the application.
- Retrieve and prepare valid test data for functional and regression testing.
- Investigate data-related failures and confirm transactional integrity.

### 🔹 HTML

- Inspect webpage structure when validating fields, links, forms, buttons, and navigation.
- Identify missing, invalid, or incorrectly displayed interface elements.
- Use HTML knowledge to provide developers with more precise defect details.
- Verify that page content is structured and displayed as expected.

### 🔹 CSS

- Evaluate webpage presentation during visual and user-interface testing.
- Identify layout problems, inconsistent formatting, alignment defects, and responsive-design issues.
- Compare expected designs with the application’s rendered interface.
- Document visual defects with screenshots, reproduction steps, and detailed descriptions.

### 🔹 Java

- Apply Java knowledge when reviewing and testing applications developed in Java-based environments.
- Review application behavior, validation rules, error conditions, and integration points.
- Communicate technical defect details to Java developers.
- Support test execution in environments that use Java testing tools and frameworks.

### 🔹 PHP

- Apply PHP knowledge when testing server-side web-application behavior.
- Validate form processing, application responses, and data passed between the interface and database.
- Determine whether defects originate in the interface, application processing, or database.
- Support functional and data-driven testing of PHP-based applications.

### 🔹 C++

- Apply C++ knowledge when evaluating compiled or legacy application behavior.
- Review processing logic, error conditions, and possible failure points.
- Communicate reproducible conditions and observed behavior to development teams.

### 🔹 JSON and XML

- Inspect structured data used in API requests, responses, configuration files, and integrations.
- Validate required fields, values, formatting, and data structures.
- Compare API data with application and database results.
- Document payloads, expected results, and integration defects.

## 🛠️ Tools & IDEs I Work With

### 🔹 Visual Studio Code (VS Code)

- My primary editor for JavaScript and TypeScript test automation.
- Use extensions for GitHub, Playwright, REST Client, and Markdown preview.
- Run automated tests and command-line tools through the integrated terminal.
- Maintain test scripts, test data, configuration files, and technical documentation.

### 🔹 IntelliJ IDEA

- Used in Java-based environments to review application code and navigate codebases.
- Supports defect investigation and collaboration with Java development teams.
- Helps identify application components related to test failures.

### 🔹 Eclipse

- Used in academic and legacy Java environments.
- Supports reviewing Java projects and executing JUnit or TestNG tests.
- Provides access to logs, debugging information, and project files during QA analysis.

### 🔹 Brackets

- Used for inspecting and making lightweight changes to HTML, CSS, and JavaScript files.
- Supports visual validation, front-end troubleshooting, and early-stage UI testing.
- Helps review webpage structure and presentation when documenting interface defects.

## 💡 Best Practices I Follow

- Connect each programming language to a specific testing or validation purpose.
- Create reusable automation functions and clear test assertions.
- Compare user-interface results with API responses and database records.
- Use valid and repeatable test data for functional and regression testing.
- Review browser output, database results, job logs, and application behavior when investigating failures.
- Document defects with reproduction steps, expected results, actual results, and supporting evidence.
- Maintain organized test scripts, test data, project folders, and README documentation.
